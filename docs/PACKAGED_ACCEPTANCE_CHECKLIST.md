## Automated backend artifact gate

Build the reviewed candidate, then run its executable acceptance harness:

```powershell
cd $env:ASSISTANT_ROOT
powershell -ExecutionPolicy Bypass -File scripts\build-backend-sidecar.ps1
powershell -ExecutionPolicy Bypass -File scripts\test-backend-sidecar.ps1
```

The harness must fail closed and prove all of the following:

- the requested port is unused before launch;
- the one-file artifact starts hidden with a fixed `MEETING_INTELLIGENCE_BACKEND_PORT`;
- `/health` remains exactly the minimal `{"status":"ok"}` contract;
- `/health/compatibility` requires `X-Meeting-Intelligence-Token` and identifies
  `meeting-intelligence-copilot`, API version `13`, backend version `0.6.1`, and enabled capability
  authentication;
- missing and invalid tokens fail closed; HTTP uses the token header and WebSocket uses
  `meeting-intelligence-v1` plus `token.<value>` subprotocols without placing the token in the URL;
- the listener is bound only to `127.0.0.1`;
- a native WebSocket receives compact v0, synthetic JA/EN/KO Meetily HTTP ingest returns the API v13
  acknowledgement, and compact v1 contains an extracted pain point but no transcript;
- authenticated session cleanup returns `reset: true`, purges the transient cache, and a late POST
  for the ended session is rejected;
- a local knowledge connector uses the packaged DPAPI/SQLite path, exposes no controlled plaintext
  marker in its database/WAL files, and returns cited read-only context;
- state-bound question-context retrieval rejects stale suggestion/version pairs, returns no raw
  provider record IDs, and times out to meeting-only behavior without delaying ASK NOW;
- remote connector health distinguishes an unchecked/degraded connection from a successful check,
  and Graph/ERP content is not retained in the encrypted local index;
- a dummy ERP connector creates and removes a real current-user Credential Manager token without
  contacting the configured endpoint, and legacy external-action approval fails closed with
  `direct_writes_disabled`;
- enterprise sources require a current 15-minute gateway lease, expired leases cannot read cached
  remote content, revocation purges the connector index, and selected-source filters cannot broaden
  access;
- documentation consistency runs return only two-citation, revisioned discrepancies; semantic
  prose claims remain proposed until reviewed; authority is neutral without a reviewed policy; and
  reviewed exports remain local draft handoff only;
- captured operational stdout/stderr stay within the one-megabyte-per-file default ceiling, contain
  neither the synthetic transcript marker nor token, and are removed after successful inspection;
  failed runs retain scoped logs and `-KeepLogs` is an explicit diagnostic option; and
- scoped Windows process-tree shutdown removes the PyInstaller child listener; and
- the acceptance-only recovery cache is always removed, including when diagnostic logs are retained.

Record the artifact path, byte count, SHA-256, cold-start timing, Defender result, and Authenticode
status for every candidate. Generated binaries, PyInstaller work files, and temporary logs remain
uncommitted.

The `0.6.1` unsigned evidence pack additionally requires the complete 108-scenario
routed-audio corpus, all 132 routed/platform acceptance results, and the SHA-256
of both the signed `large-v3-turbo-q5_0` artifact manifest and its detached
signature. Korean remains synthetic-tested until routed audio and human review
are completed; source and text-corpus success must not be presented as natural-speech acceptance.

## Clean Meetily lifecycle gate

Use `$env:MEETILY_ROOT` from distribution-hardening commit `58f26bb` or a reviewed
descendant on the current release branch. Its setup script must receive the real backend artifact
explicitly:

```powershell
cd $env:MEETILY_ROOT
$env:RUSTUP_TOOLCHAIN = "stable"
$env:LIBCLANG_PATH = "<path-to-LLVM-bin>"
$env:CMAKE_GENERATOR = "Visual Studio 17 2022"
powershell -ExecutionPolicy Bypass -File scripts\setup-meetily-sidecars.ps1 `
  -MeetingIntelligenceBackendPath `
  $env:ASSISTANT_ROOT\dist\backend-sidecar\meeting-intelligence-backend-x86_64-pc-windows-msvc.exe
```

Required lifecycle evidence:

- release builds manage the sidecar by default, development builds remain manual by default, and
  `MEETING_INTELLIGENCE_MANAGE_SIDECAR=0` explicitly disables management;
- a compatible existing loopback backend is reused and is not owned or stopped by Meetily;
- managed mode generates a strong token in process memory, passes it only to the child backend,
  authenticates Rust HTTP plus frontend fetch/WebSocket, and clears the owned token on shutdown;
- a non-loopback `MEETING_COPILOT_URL` is rejected by the existing local-only validator;
- the bundled backend is retained only after the exact compatibility handshake succeeds;
- startup failure does not block Meetily, recording, or local STT;
- Meetily stops only the process tree it started;
- two consecutive authenticated health failures trigger at most three automatic restarts at
  1/2/4 seconds, and 60 seconds of stable runtime resets that budget;
- exhaustion stops automatic retries, exposes privacy-safe status, and permits explicit manual retry;
- missing executable, incompatible backend, startup failure, and stopped/unhealthy backend render
  actionable JA/EN guidance from fixed reason codes; no path or exception text enters the webview;
- stale ASK NOW content is cleared throughout outage/recovery; and
- ignored real-artifact Rust tests confirm listener disappearance after shutdown and a new healthy
  PID after an owned backend crash; and
- fixed privacy-safe lifecycle event codes rotate across at most two operational files capped at
  256 KiB each, without tokens, transcript text, raw backend errors, or development paths.

The focused lifecycle/transport tests, intelligence presentation tests, full Rust library suite,
`cargo check --locked`, frontend `tsc --noEmit`, and Next production build must pass.

## Packaged GUI and speech gate — still required

payload pass:

  `synthetic_manual_work.wav`;

The panel's absent/recovering behavior and recording independence have automated component/native
coverage, but that is not a substitute for the final packaged GUI run.
